## 本日発見した重要な知見（本に書くべき）

### 知見1：Fusion は全コマンドで Core より速い、最大は compile cold で7倍超
- 最大差は **compile cold（7.13×）**。Fusion の Rust製パーサ・ローカル型チェックの強みが明確に出た
- compile warm も 6.21× と高倍率を維持
- run の差が 2.5〜2.7× と最小（Snowflake 側のクエリ実行時間が支配的になるため、これは予想通り）

### 知見2：test の cold/warm 差がほぼゼロ
- Core 0.5%、Fusion 10.0%（他コマンドは18〜30%）
- 仮説：test の処理時間は Snowflake にテストSQLを投げる時間が支配的で、dbtプロセスの起動オーバーヘッドが相対的に小さい
- 本に書くべき：「test における cold/warm 差は dbt のキャッシュよりも Snowflake のクエリ実行時間が支配的」

### 知見3：Core の再現性は極めて高い（平均CV 4.4%）、Fusion はバラつきあり（平均CV 16.2%）
- 特に Fusion parse cold は CV 39.1%（0.79〜2.027秒、約2.5倍のレンジ）
- 仮説：絶対値が小さい（1秒前後）ため、同じ絶対変動でもCV%が大きく見える
- Fusion を本で評価する際は「平均が速い」だけでなく「ばらつきもある」も書くべき

### 知見4：見積もりは1h40m、実測は56分（44分短縮）
- cold phase の70秒待機が予定通り効いた一方、warm phase が想定より高速だった
- 5モデル前後の小規模プロジェクトでは、本計測の所要時間見積もりは保守的すぎたと言える
- 本に書くべき：「自分のプロジェクトで再現する読者向けの参考時間として 86回 × Y1 = 約1時間」

### 知見X：Fusion preview 版の機能制約（dbt docs generate 未サポート）
**※ 観測は 2026-06-13 の本計測中。発覚は 2026-06-14 の会話で生ログを精査した際**

- Fusion 2.0.0-preview.183 では `dbt docs generate` 実行時に以下の警告が出力される：
  ```
  [warning] [DocsGenerateWarning (dbt1705)]: `dbt docs generate` is not supported.
  Use `dbt compile --write-catalog` to write catalog.json.
  ```
- 3回とも 506ms / 515ms / 615ms で終了（exit_code=0）
- 本計測時点では「Fusion は docs generate が17倍速い」として simple_report.md 初版に記載していたが、これは Fusion が実処理をスキップして警告終了している時間との比較であり、誤解を招く
- 本計測の翌日（6/14）に simple_report.md を訂正、決定16として意思決定ログに方針を明文化
- 未確認：`target_fusion\` 配下に catalog.json / index.html が生成されているか（次のタスクで実機確認予定）
- 本に書くべき：「Fusion は preview 段階のため、Core で動くコマンドの一部が未サポート。`dbt docs generate` はその一例で、代替として `dbt compile --write-catalog` が案内されている」
